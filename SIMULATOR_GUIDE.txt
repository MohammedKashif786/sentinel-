SENTINELML SIMULATOR GUIDE
========================

Overview
--------
SentinelML is an educational adaptive endpoint-security simulator. It demonstrates how endpoint telemetry can be scored by temporal and graph-based signals, fused into a risk score, and mapped to graduated responses. The browser simulator is an interactive illustration of that pipeline; it does not load or execute the trained PyTorch models. The Python project contains the separate data-generation, model-training, and evaluation pipeline.

Opening the browser simulator
-----------------------------
Latest v0 workspace preview: https://sentinelml-visual-redesign-sentinelml-updated-e881664f5b9a9813.v0.build

This is a workspace preview rather than a production deployment. It is available while the preview service is running; deploy the project to Vercel for a permanent public URL. The standalone browser experience is in sentinelml-site/index.html. In this workspace it is served from sentinelml-site on port 4174. The left navigation switches between the simulation and model/data/policy explanations without leaving the page.

Simulation view
---------------
The Simulation view has two separate modes:

1. Live Simulation
   - Choose the number of endpoints, select an endpoint, and inject one of three illustrative scenarios: Beaconing / Slow Exfiltration, Lateral Movement / Port Scan, or Coordinated Multi-Host.
   - Stop the selected attack or all attacks, run the demo, pause, reset, and adjust the simulation speed.
   - Telemetry, LSTM-style temporal risk, GNN-style graph risk, fused risk, and response status update as the simulation advances. These values are generated by browser-side demonstration logic, not predictions from the trained model files.

2. Replay Trained Run
   - Replays the built-in h4 evaluation trace, or recorded rows from an uploaded CSV. Replay controls replace the live attack and endpoint-count controls.
   - Use the time scrubber, Play/Pause, 1x/2x/5x speed, or jump buttons for the attack at t=2400 and isolation at t=2456.
   - The built-in sequence rises to Monitor at t=2415 (risk 30), Restrict at t=2429 (risk 60), and Isolate at t=2456 (risk 92); it peaks at risk 97 at t=2522 and recovers through the configured thresholds to Normal at t=2646.
   - Replay banner metrics are Fused F1 0.984, ROC-AUC 1.000, and baseline F1 0.976.

CSV replay format
-----------------
Upload a CSV containing these required columns: t, host, conn_freq, lstm_risk, gnn_risk, risk, level, status. Each row is a host observation at time t. Time and metric columns must be numeric; host names may use letters, numbers, periods, underscores, and hyphens. Up to 12 distinct hosts are supported. The replay is built from the uploaded rows; level/status values determine the response when supplied, otherwise risk thresholds are used.

Network topology and response
-----------------------------
The SVG network diagram places the server and switch in the core tier and endpoint hosts in an organic cluster. Endpoints have switch uplinks and peer-to-peer communication links. Select a node with a mouse or keyboard to highlight it and its one-hop peer neighbors. Thicker links indicate more activity; amber dashed edges indicate anomalous peer traffic; red dashed links and the quarantine badge indicate isolated endpoints. Status colors distinguish normal, monitored, restricted, and isolated states. Green, amber, and red are reserved for response/risk states; cyan and violet identify model signals and highlights.

The default browser policy uses Monitor above risk 30, Restrict above 60, and Isolate above 80. The response is hysteretic: when risk falls, the state steps down only after sustained low risk. The response log, escalation/recovery log, and audit log record state transitions. The endpoint table and risk chart show the current and recent state. Top Risk Drivers provides illustrative feature contributions for the selected host.

Other simulator sections
------------------------
- Data & preprocessing: shows example telemetry, normalization, and sliding-window inputs used to explain the pipeline.
- How the models were trained: summarizes training steps and evaluation results from the Python project.
- How the LSTM works: illustrates temporal sequence input, reconstruction, and risk scoring.
- How the GNN works: explains graph neighborhoods and message passing.
- Risk fusion: explains how temporal, graph, authentication, and traffic signals combine into risk.
- Admin policy: lets users validate and apply response thresholds and inspect example rules. The browser policy playground uses a rule-based demonstration; the Python pipeline can optionally use a local LLM as described in README.md.

Python model pipeline
--------------------
The repository README.md documents running the Python data generator, training the LSTM autoencoder and GraphSAGE GNN, evaluating/fusing their scores, and launching the Streamlit dashboard. That pipeline is separate from the static browser simulator. The outputs/ directory contains generated model artifacts, result CSV data, metrics, logs, and figures.

Limitations
-----------
This project is a simulation and learning aid, not a production endpoint-protection system. The browser demo does not inspect real network traffic, run the trained weights, enforce operating-system controls, or isolate real devices. Real containment in the Mininet example is represented separately by Open vSwitch flow rules.
